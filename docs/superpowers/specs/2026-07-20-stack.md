# Stack
**Status:** Current (as of 2026-07-27)
**Module:** `client/app/board/html/stack.ts`, `client/app/board/geometry/stackLayout.ts`, `client/app/game/intents.ts`, `client/app/board/motion/flights.ts`

## Problem Statement

The board needs a stack surface that stays readable at different viewport sizes, shows incoming spells and abilities, supports targeting into stack objects, and lets the server pause helpless auto-resolve while the player is inspecting the stack.

## Solution

Render the stack as a right-edge DOM overlay with three presentations: pile, expanded strip, and full grid. Geometry helpers choose the presentation and peek spacing from viewport height and stack count. Stack entries carry `MessageRef` labels from the wire and the overlay formats them with `formatMessage`. Hover dwell emits a server command, and canvas flights with `kind: "stack"` hide the matching resting stack face while flying.

## User Stories

- As a player, I can see the top stack object without losing battlefield space.
- As a player, I can expand a crowded stack into readable cards.
- As a player, I can see Island Blue arrows from stack spells/abilities to their declared targets.
- As a player aiming at a stack object, I can click a highlighted stack face to choose it.
- As a player with priority, hovering the stack prevents helpless dwell timing from racing ahead.
- As a player, I can see the stack-hold countdown while a hold remains without hovering the stack.
- As a player, stack entrances and flight ownership do not create duplicate faces.

## Behavior

- Pile mode peeks cards from the right edge and shows the top object caption or staged target hint.
- Expanded strip shows object names and card art in one row when space allows.
- Full mode uses a centered multi-row grid for large stacks.
- `StackObjectView.label` is a `MessageRef`; spells use card-name refs, abilities use effect refs, and the client formats both at the view edge.
- `StackObjectView.print` / `name` / `card_id` carry the source card's art identity. The overlay prefers a live `objects` join on `source`, then falls back to these fields when `source` is omitted from `objects` — a Moved tombstone (Evolving Wilds) or a ceased token (`Object::Removed`, Food/Clue sacrifice, Dies triggers).
- `stackPeekFor`, `stackPresentation`, `stackStripPeek`, and `stackFullPerRow` calculate layout.
- `StackDwellChanged({ dwelling })` fires on stack hover only when the viewer has priority and the stack is non-empty.
- While `stack_hold_remaining_ms > 0` (and no staged ghost), `stack-hold-bar` is fully visible — not hover-gated.
- `SetStackDwell` calls `/api/rpc` through `Game.SetStackDwell`.
- Resting stack faces hide only while a canvas flight with `kind: "stack"` owns that object id. Battlefield / from-stack flights for an ability's source permanent do not blank the ability face (the pile caption alone is not enough).
- A staged target ghost appears in pile mode when arrow aiming needs a stack origin.
- A pending board-aim ghost appears the same way when the engine pauses with no stack entry for the choice source: ability placement before push (`choose_target` / `Placement::Paused`, Innkeeper's Talent begin-combat) and mid-resolution onboard card-picks after the ability left the stack (`proliferate`, `phase_out`, sacrifice edicts, and other `ONBOARD_CARD_PICK_KINDS` with a `source` / `attachment`). The ghost uses the source permanent's live `objects` art. When the source is already a stack entry (post-cast spell targeting, or an instant/sorcery still finishing), no second face is added and the aim origin stays on that entry.
- Declared `stack[i].targets` values, with `stack[i].target` as the fallback, paint one Island Blue arrow per resolvable destination via `stackTargetArrowShapes` / Mount `paintStackTargetArrows` (layer 4, above resting permanents — not the Foldkit Canvas under card art).
- Pile top caption and strip target chrome list all resolved target labels joined with `, ` after ` → `.

## Implementation Decisions

- The stack remains DOM in layer 5, while arrows and flights are painted on their board layers.
- The stack aim origin is shared with targeting so arrows point at the same right-edge pile players see.
- Stack→target arrows use `stackFaceScreenOrigin` for the active presentation so expanded/full faces own their arrow tails.
- While arrow-aiming, legal stack faces set `data-legal-target="true"` (and staged ghosts `data-staged="true"`) and paint Island blue rings via Tailwind `data-[…]:ring-island-blue`; legal faces dispatch `TargetChosen` on click.
- Dwell is server state; the client does not locally decide stack-hold outcomes.
- `cardArt(h, opts)` supplies stack card faces and supports optional sizing style.
- Stack faces resolve print/name/`card_id` from the live object when present, else from the stack entry fields projected for Moved sources.
- Missing catalog keys render raw keys in stack captions rather than falling back to server English.

## Testing Decisions

- Geometry tests cover pile/strip/full presentation and peek calculations.
- Unit tests cover `stackTargetArrowShapes` for object/player targets, multi-target rows, and skips when unresolved.
- Bitmap paint tests assert declared stack→target arrows paint on the Mount layer above resting card art.
- Scene/outcome tests cover legal stack-face highlight (`data-legal-target="true"`) and click → submit while Counterspell-style aiming.
- Scene tests cover pile, expanded, staged hint, hold bar, hidden stack-flight faces, ability art during source battlefield flights, ability art from entry `print` when the source id is absent from `objects`, pending `choose_target` source art while the ability is not yet on the stack, pending `proliferate` source art after the ability left the stack, no duplicate ghost when the spell source is already on the stack, and multi-target captions.
- Stack projection and Scene tests assert MessageRef labels format into user-facing captions.
- Board update tests assert `StackDwellChanged` emits `SetStackDwell`.

## Out of Scope

- Canvas-painted stack cards.
- Client-side simulation of stack-hold timeout.
- New stack targeting rules beyond legal targets sent by the engine.

## Further Notes

- The stack overlay is below prompts, HUD, and the inspect dock in the board layer stack.
- Stack yield controls live in the priority chrome spec.
